## 3. ⛔ 반드시 알아야 할 함정 (오늘 실측으로 밝힌 것)

1. **`DRJIT_NUM_THREADS`·`MI_NUM_THREADS` 는 없는 이름이다** (drjit 1.3.1 · mitsuba 3.8.0).
   환경변수로 걸어도 `dr.thread_count()` 가 **192** 다. `dr.set_thread_count()` 를 **불러야** 걸린다.
   ⇒ `benchmark/elevation_sweep_md.py` 가 import 직후 `thread_guard.apply()` 를 부른다.
2. **`os.cpu_count()` 는 192, cgroup 할당은 12.** 무엇을 나눌 때든 cgroup 을 봐야 한다.
3. **`/proc/meminfo` 는 호스트다.** 우리 천장은 `memory.max` = **32 GiB**.
4. **`os.getloadavg()` 도 호스트다.** 우리 사용량은 `/sys/fs/cgroup/cpu.stat` 의 `usage_usec`.
5. ⭐**못 재면 «막는 쪽» 으로 물러선다**(fail-closed). 호스트 값으로 물러서면 브레이크가
   조용히 영구 해제된다 — 오늘 이 실수를 **세 번** 했다.
6. **PathSolver 는 같은 코드로도 비트가 다르다** — 경로가 배열에 담기는 **순서**가 매번 달라서다.
   시드는 잘 작동한다. `--det`(지연→실수부→허수부 정렬)이면 완전히 고정된다.
7. **개선 커널의 K≥2 는 쓰면 안 된다** — 값이 `--nshards` 를 탄다(0.118~0.328 dB).

- 「씬 재사용이 값을 오염시킨다」는 **틀림** — **씬** params 면 비트동일, **메쉬** params 면 오염

- 겉·속이 메쉬를 **공유**한 채 씬 재사용 → **8.70 dB** 어긋난다

### ⭐ 오늘 배운 것 — 같은 실수를 **네 번** 했다
「선언은 했는데 **안 걸리는** 안전장치」. 스레드 캡 · CPU 브레이크 두 번 · GPU 커널 가드 둘.
