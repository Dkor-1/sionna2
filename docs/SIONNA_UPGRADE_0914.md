# 솔버 판 갈이 — 2.0.1 → 2.1.0 (2026-09-14)

사용자 지시(2026-09-14): 「시오나 업데이트해서 작업하고 싶어. 기존 결과는 다 유의미하게 쓸 수
있다고 생각되는데 나는 굳이 가상환경을 따로 만들기보다는」 · 시점은 「큐가 빠진 뒤」.

⇒ **제자리 업그레이드**한다. 가상환경을 새로 만들지 않는다.

## 무엇이 바뀌나 — 예행 실측

```
drjit 1.3.1 → 1.5.0 · mitsuba 3.8.0 → 3.9.1 · sionna 2.0.1 → 2.1.0 · sionna-rt 2.0.1 → 2.1.0
```

`uv pip install --dry-run` 이 **네 꾸러미만** 바꾼다고 냈다. 나머지 66 개는 그대로다
(numpy 2.5.2 · torch 2.11.0+cu128 포함). 되돌림 기록은 `runners/env_freeze_20260914_sionna201.txt`.

⚠**우리 커널도 영향을 받는다** — `src/rcs_sbr.py:80-82` 가 mitsuba·drjit·sionna.rt 를 직접
임포트한다. 「PathSolver 팔만 바뀐다」가 아니다.

## ⭐기존 결과는 왜 그대로 쓸 수 있나

| 근거 | 확인 |
|---|---|
| 창고 샤드 **7,730 개가 전부** 2.0.1 설치 시각(08-13 00:24) 이후다 | `find -newermt` 전수 |
| 그 이전 판으로 구운 샤드가 **0 개**다 | 같은 셈 |
| 2026-09-14 이후 샤드는 판을 **스스로 적는다**(`solver_build`) | `bake_stamp()` |

⇒ 「이름에 판 꼬리표가 없다」 = 「2.0.1 로 구웠다」로 읽는다.
⛔다만 이것은 **추론**이다 — 7,704 개는 도장이 없다. 도장이 있는 29 개만 «적힌» 것이다.
  창고 사실이 뒷받침하지만, 원장에 2.0.1 이라고 **적어 넣지는 않는다**(안 적힌 것을 적힌 것처럼
  만들지 않는다). 판독기는 도장 없는 행을 「적히기 전 세대」로 읽는다.

## ⛔이름이 같으면 — 덮어쓰는 게 아니라 **조용히 건너뛴다**

사용자 물음(2026-09-14): 「안 덮어쓰게 실행을 하면 되는 거 아니니?」
⇒ **코드를 읽고 고쳤다.** 기본 동작은 덮어쓰기가 아니다:

```python
# elevation_sweep_md.py:651 · :774
if shard_done(f) and not a.overwrite:      # ← 있으면 건너뛴다
```

같은 이름으로 2.1.0 을 돌리면 갈래가 **둘뿐**이고 **둘 다 못 쓴다**:

| 어떻게 돌리나 | 무슨 일이 나나 |
|---|---|
| 그냥 (기본) | 샤드가 이미 있으니 **몇 초 만에 «건너뜀»으로 끝난다.** 2.1.0 자료는 **0 개**인데 잡이 전부 rc=0 이라 성공처럼 보인다 |
| `--overwrite` | 2.0.1 샤드를 **지우고 덮는다.** 비교하려던 상대가 사라진다 |

⭐첫 줄이 2026-08-17 사고 그 자체다 — 메쉬 수리를 기본으로 켰는데 이름이 그대로라 러너가
**옛 메쉬로 낸 샤드를 재사용**했고, 작업이 3~4 초 「건너뜀」으로 끝나 재계산이 통째로 무효였다.
(`elevation_sweep_md.py` 의 `tagmf` 주석이 그 사고를 적어 둔 자리다.)

⇒ **한 이름에는 한 판밖에 못 담는다.** 「안 덮어쓰게」로는 두 판을 같이 가질 수가 없다.
  그래서 이름을 가르는 것 말고 길이 없다 — 그것이 판 꼬리표다.

| 어디 | 무엇 |
|---|---|
| `benchmark/elevation_sweep_md.py` | `BUILD_BASELINE` · `build_tag()` — 기준 판이면 **빈 글자**, 2.1.0 이면 `_rt210` |
| `src/arm_grammar.py` | `_F("solver_build", "rt", …)` — 되읽기·되짓기 |
| `benchmark/check_solver_build.py` | 상시 검사 ①~④ |

값은 싸다 — 함수 하나와 문법 한 줄이고, 2.0.1 에서는 **이름이 한 글자도 안 바뀐다**(예행 확인).

⛔**이름이 못 담는 차이는 빌더가 멈춘다** — sionna-rt 는 기준 그대로인데 mitsuba·drjit 만
움직이면 꼬리표가 안 붙어 다시 「건너뜀」이 된다. 그 경우 `build_tag()` 가 예외로 선다.
「조용히 건너뛰기」보다 「서서 사람을 부르기」가 낫다.

⭐꼬리표가 생기면 2.0.1 팔과 2.1.0 팔이 **한 축만 다른 대조군**이 된다 —
`check_arm_names.py --groups solver_build` 가 그대로 묶어 준다.

## 절차

1. **워커가 0 이 될 때까지 기다린다.** 큐가 빠지기 전에 올리면 도는 워커가 옛 바이너리와
   새 파이썬 코드를 섞어 읽을 수 있다. ⚠판 도장은 임포트 때 찍히므로 **라벨은 안 틀린다**.
2. `taskset -c 8-11 uv pip install --python /workspace/.venvs/py312/bin/python \
   "sionna==2.1.0" "sionna-rt==2.1.0"`
3. `benchmark/check_solver_build.py` — ①~④ 전부. ⭐④ 가 `deterministic` 을 찾아낼 자리다
   (2.0.1 에는 `__init__`·`__call__` 어디에도 **없다**. 2026-09-14 실측).
4. 연기 시험 한 칸 — 작은 자세 수로 굽고, **이름에 `_rt210` 이 붙는지**·도장이 2.1.0 인지 본다.
5. `runners/jobs_0931_bridge.txt` 를 `filter_jobs.sh` 로 거른 뒤 발주한다.
   ⚠**업그레이드 뒤에** 걸러야 한다 — 2.0.1 에서 걸면 꼬리표가 없어 전부 DONE 으로 나온다.
