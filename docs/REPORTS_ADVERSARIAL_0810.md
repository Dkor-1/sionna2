### 6.7 freespace_link.py:207 판정 (요청된 코드 정밀 판독)

- **:207 이 기록한 원 버그는 죽었다** — `n0_effective` 의 `b_noise_hz` 기본값 1.0(DPI 잔류 전력을 1 Hz 에 몰아넣어 +10log₁₀B ≈ +75 dB 부풀림)은 제거됐고, `src/freespace_link.py:211–215` 가 «b_noise_hz=1.0 + 유한 eca_depth» 조합에서 ValueError 를 던지는 가드로 박혀 있다.
- **그러나 «라벨 굳음» 패턴 자체는 상류에서 살아 있다** — `src/experiment_freespace_range.py:496` 이 `n0_at = fsl.n0_effective(Pdir, NF_DB, fs, eca_depth_db=60.0)` 으로 **하드코딩된 60 dB 가정**의 잡음 분해를 `classify_limit()`(:500)에 먹인다. 헤드라인 solve 는 이상 소거(잔류 0, `R_m == sensitivity_eca_depth.inf.R_m` 소수 12자리 일치)에서 풀리는데 라벨은 60 dB 팔에서 분류되므로, DNR(≈75 dB) > 60 인 모든 셀에서 `limit="dpi_residual"` 로 굳는다 — 원장 실측으로 W1·L1·G1 전부 그 상태다. `limit_note`("not headlined")는 있으나 라벨 키에 조건(가정 깊이)이 안 실려 H1 형 오독을 만든다. 커널·실험 코드는 상류라 손대지 않았고, 리포트 축은 라벨 인용 제거(H1)로 차단했다. 고치는 자리: `experiment_freespace_range.py:496` 의 깊이를 헤드라인 동작점과 일치시키거나 라벨을 `limit_at_depth60` 류로 개명.
