## ⓒ 기하도 아니고 회전도 아니다

- 낙차 자세 번호를 날개 박자·로터 회전·반박자 주기로 Rayleigh 검정: p = 0.44 / 0.41 / 0.44 (el 0),
  0.36 / 0.21 / 0.18 (el −30). **각도와 무관하다.**
- 낙차 사이 간격이 **지수분포**다(KS p = 0.59, 0.68) — 자세 번호에 대한 **푸아송 과정**.
- PRF 를 19,700 → 157,600 으로 올려 로터 회전량을 1/8 로 줄여도 개수가 36/33/39/33 로 그대로다.

## ⓓ 표적 크기·회전 속도 가설은 기각됐다

- **같은 물리 크기**인 두 메쉬(mavic4pro 0.5957 m · matrice4e 0.5947 m, 0.16 % 차)가
  발생률에서 **2.39 배** 다르고, mavic4pro 가 16/16 칸에서 높다.
- **3.29 배 차이** 나는 두 메쉬(mini5pro 0.2218 m · s1000plus 0.7302 m)는 구분이 안 된다(Wilcoxon p = 0.2308).
- 같은 메쉬를 **배율만** 바꾼 사다리에서는 **클수록 많아진다**(x0.7→x3.0 에서 35→59, log-log 기울기 +0.349±0.074).
  그런데 **프레임만** 키우면 부호가 뒤집힌다(−0.525±0.065). 부호가 부품마다 바뀌는 양은 크기 법칙이 아니다.
- ⇒ **크기가 아니라 «어느 메쉬인가» 가 정한다.**

## ⓔ ⛔누구 탓인지는 아직 모른다 — 우리 하네스가 용의선상에 있다

`benchmark/elevation_sweep_md.py:695-707`

```python
hit = (O != RP.NO_OBJ).any(axis=0) if O.size else np.zeros(aa.size, bool)
_t  = aa[hit] * np.exp(-1j * 2 * np.pi * fc * tau[hit])
E[j] = complex(np.sum(_t));  npaths[j] = int(hit.sum())
```

물체 ID 가 `NO_OBJ` 로 돌아온 경로는 **합에서도 `npaths` 에서도 함께 사라진다.**
⇒ 「PathSolver 가 못 찾았다」와 「돌려줬는데 우리가 버렸다」의 **서명이 똑같다.**

⭐**고친 것**: `nret`(마스크 **전**, 돌려받은 경로 수)을 샤드에 함께 적게 했다(2026-09-02).
앞으로 나오는 샤드에서는 `nret` 과 `npaths` 를 견주면 바로 갈린다.
⚠**옛 샤드에는 `nret` 이 없다** — 옛 자료로는 이 갈림을 못 짓는다.

기각된 다른 후보들:
- **언더플로** — 기록의 \|E\| 최솟값이 5.9e−8. float32 최소 정규수보다 30 자릿수 위. 저장은 complex128. ⛔
- **경로 버퍼 넘침** — 본 최대 npaths 18,398 대 상한 2,000,000 (0.92 %). ⛔
- **합 순서 / 단정밀도 상쇄** — 재실행끼리 정상 자세가 1.6e−16 로 일치한다. 순서는 마지막 비트를
  움직이지 자세를 33 % 움직이지 않는다. ⚠`--det`(정렬)은 이걸 **못 고친다** — 애초에 안 돌아온
  경로를 되살릴 수는 없다. ⛔
- **난수 씨앗** — `seed=1` 하드코딩인데도 답이 바뀐다. ⛔

## ⓕ 「우리 커널엔 없다」는 우월성의 증거가 아니다

전 코퍼스에서 우리 커널은 **0/401 기록**(3,330,048 자세)이고 PathSolver 는 390/1,049 다.
⚠그런데 **우리 커널은 구조적으로 이 실패를 낼 수 없다** — 고정된 결정적 광선 격자 위에서
합하므로(`src/rcs_sbr.py:1096`) **열거할 «경로 목록» 자체가 없다.** rep1 vs rep2 가 비트동일이다.
⇒ 「0 개」는 **알고리즘 부류의 성질**이지 우리 커널이 낫다는 증거가 아니다.

⚠우리 커널에도 한 자세짜리 깊은 골이 있다(71 개, 최저 r = 5.585e−4). **다만 그것들은 위상이 돈다**
(중앙 \|Δ위상\| 0.45~3.09 rad) — 간섭 골이다. PathSolver 것은 위상이 그대로다(p50 2.31e−4 rad).

### ⓐ 얕은 계단(2/3) — 기작이 갈렸다: Sionna 2.0.1 의 해시 경합

`sionna/rt/path_solvers/sb_candidate_generator.py:484-498` 이 정반사 사슬을 해시 통으로
중복제거하는데, **먼저 원자적으로 통을 올린 스레드만** 그 경로를 남긴다:

```python
samples_counter = dr.scatter_inc(specular_chain_counters[i], counter_ind, new_specular)
new_specular &= samples_counter == 0
```

주석에 race condition 이 적혀 있다. GPU 스레드 순서에 따라 **경로가 통째로 사라진다**
(순서만 바뀌는 게 아니다). 그래서 `--det`(정렬)로는 못 고친다 — 안 돌아온 경로는 못 되살린다.
`spec_counter_size = max(max_num_paths_per_src, 1e6)` 이므로 **우리가 넘기는
`max_num_paths_per_src`(현재 2,000,000)가 해시 통 수**다.

⭐**우리가 이미 재 놨다**(2026-08-16, `outputs/depth_axis_verdict_0816.json :
null_bands.pathsolver_repeatability`): 회절 끔 1.9e-15 dB / **회절 켬 8~26 자세, |E| 최대 23 %**.
`docs/AUDIT_REPORTS_0901.md` A-1 이 「리포트에 이 비결정성이 한 줄도 없다」고 이미 지적했다.

### ⓑ 깊은 전멸(−51 dB) — **비결정성이 아니다. 기작 미상**

- 25 판 전부 `|E| = 2.988340e-07` 로 **비트 동일**하다. 원장 값과도 같다.

## ⓔ 계단의 «분모» N — 무엇이 정하나 (2026-09-02 저녁)
