## 1. 왜 갈아엎나 — 실측한 현실

| | 현재 |
|---|---|
| 리포트 | 본편 **13편** + 부록 **8편** = 21 |
| 코드 | src 81파일 33,990줄 + benchmark 34파일 13,174줄 = **47,164줄** |
| 재생성 파이프라인 | **26단계**, 직렬 **11.9시간** |
| 미커밋 | 239파일 |

그리고 조사가 밝힌 것:

- **주장의 상당수가 방어 불가**다 — 절대 σ(앵커 1개), 밴드 기울기(측정의 3~8배), 자세별 바이스태틱(상반성 25 dB 위반)
- **검증되지 않은 축을 헤드라인으로 삼고 있었다**
- 게재된 선행 6편 중 **표적 산란을 계산한 것은 0편**이다 — 전부 재거나, 피팅하거나, 정확도를 주장하지 않는다

즉 **문제는 작업량이 아니라 "지지되지 않는 주장을 향해 작업량을 쏟고 있었다"** 는 것이다.

## 2. 새 골격 — 6편

기준: **각 편이 "무엇을 주장하고, 그 주장이 무엇으로 지지되는가" 를 한 문장으로 말할 수 있어야 한다.**

### 01 · 선행연구 — 무엇이 가능하고 무엇이 아닌가
**주장**: 드론 메쉬로 산란을 계산해 게재된 전례가 없고, 회피한 논문들은 각각 무엇을 포기했다.
**지지**: 아카이브 55편 census(정독 26편), 게재상태 PDF 메타로 확정.
**핵심 절**: §3 회피전략 카탈로그(측정 / 피팅모델 / 외부 full-wave 주입 / stock 방치 / 해석적 블레이드 / 표적모델 없음).

### 02 · 표적 모델 — 메쉬·엔진·앵커
**주장**: 자세 구조는 기하에서, 레벨과 주파수 의존성은 측정에서. 그 경계를 수치로 명시한다.
**지지**: kr 스윕(해석PO 대비 ≤0.201 dB, 21점 48입사) · PO 모델 바닥(밴드별 envelope) · Das 앵커.
**합침**: 현 02(메쉬)+03(형상검증)+06(RT 한계)+07(SBR 엔진)+08(RCS 결과).
⭐ **이 편의 존재 이유**: 우리만 가진 것 = **부품별 재질 + 광선추적 가림**. Proc.IEEE 조차 stock 이다.

### 03 · 조명원 — 세 파형과 그 대가
**주장**: 점유·대역폭·PRF·λ² 가 만드는 격차. **전부 σ 와 무관하게 정확한 양이다.**
**지지**: 파형 사양 + Sionna PHY 검증.
**합침**: 현 04+05.

### 04 · 검출기 — ECA · 거리도플러 · CFAR 교정
**주장**: 명목 Pfa 가 경험 Pfa 와 얼마나 다른지, 그리고 그것을 교정하지 않으면 파형 비교가 성립하지 않는다.
**지지**: `verify_cfar.json`(2717 s 실측), `verify_eca.json`, 모호함수.
⭐ **문헌 공백**: OpenISAC 은 `CFAR`·`false alarm`·`detection probability` 가 **0회**다. 실측 논문은 Pfa 통제가 불가능하다. **통제 시뮬만 할 수 있는 일**이다.
**합침**: 현 10+11 일부.

### 05 · 검출 결과 — 모노/바이 × 근/원거리
**주장**: 자유공간에서 어느 조명원·몇 개 수신기로 어느 거리까지 보이나.
**지지**: 검출 헤드라인 + 감도사슬 + 자유공간 기하.
**합침**: 현 09(일부)+11(일부)+12+13.
⚠ **밴드 간 비교는 앵커 σ 위에서만** 말한다.

### 06 · 실측 계획과 검증
**주장**: 무엇을 재면 시뮬의 어느 주장이 결판나는가.
**지지**: matrice4e·mini5pro 측정 설계(기준체·배경차감·원거리장·자세통제).
**역할**: 이 편이 **다음 라운드의 계약서**다.

## 5. ⭐ 서술 규약 (2026-07-31 재정립) — 한 일을 쓴다

사용자 지시:
> "레포트가 뭐가 아니고 뭘 안했다 이런 설명이 너무 많아서 꼴보기 싫어. **뭘 했냐 위주로** 재구성해."
> "**방어적 표현을 빌리지 않아도 괜찮은 내용으로** 구성해서 작성해."
> "앞서 만든 규칙들 자체를 새롭게 정립하면서 작업해."

### 5.0 ⭐ 원리 — 주장의 크기를 맞추면 변명이 필요 없다

이전 규약은 "주장하지 않는 것" 표와 "한계" 절을 **필수**로 박았다. 그 결과 모든 편이
변명으로 시작해 변명으로 끝났다. 잘못된 설계였다.

**방어적 표현이 필요하다는 것은 문장이 실제보다 크게 말하고 있다는 신호다.**
고칠 곳은 표현이 아니라 **주장의 크기**다. 크기를 정확히 맞추면 그냥 사실이 되고,
사실은 방어할 필요가 없다.

| 방어적 (금지) | 크기를 맞춘 문장 (같은 정보, 방어 0) |
|---|---|
| "절대 σ 가 맞다고 주장하지 않는다" | "자세 패턴은 기하에서 계산했고 레벨은 Das 측정에 맞췄다" |
| "PO 근사라 한계가 있다" | "해석 PO 구 대비 0.201 dB 안에서 일치한다" |
| "이 결론은 잠정적이다" | "β ≤ 45° 에서 성립한다" |
| "편파를 통제하지 못했다" | "편파: VV 단일. 실측에서 2편파로 확장한다" |
| "n=1 이라 일반화할 수 없다" | "앵커 기체 1종. phantom4 는 동급, s1000plus 는 3배 크다" |

오른쪽은 왼쪽보다 **정보가 더 많고 더 짧다.** 그것이 목표다.

### 5.1 불확실성은 **수치**로 쓴다, 산문으로 쓰지 않는다

수치는 방어가 아니다. `크기 전이 L² vs L⁴ = 9.50 dB` 는 사실이지 사과가 아니다.
불확실한 양이 있으면 **표에 숫자로** 넣어라. 산문으로 "주의해야 한다"고 쓰지 마라.

### 5.2 모든 편의 여는 블록 — 5개, 전부 능동태

```
┌─ 한 일 ─────────────────────────────────────────┐
│ 한 문장. "…를 했다" 로 끝난다. 물음표 아님.       │
├─ 결과 ──────────────────────────────────────────┤
│ 3~5줄, 숫자로. 여기만 읽어도 결과를 안다.         │
├─ 방법 ──────────────────────────────────────────┤
│ 어떻게 얻었나. ⭐ 범위는 여기서 자연히 드러난다 —  │
│ "Das 측정에 맞췄다" 가 곧 "레벨은 측정 출처" 다.   │
├─ 재현 ──────────────────────────────────────────┤
│ 명령 + 출력 JSON + 소요시간.                      │
├─ 앞 편에서 ────────────────────────────────────┤
│ 무엇을 알고 와야 하나. 없으면 생략(쓰지 마라).     │
└─ 본문 ──────────────────────────────────────────┘
```

바뀐 점: **"주장하지 않는 것" 표를 없앴다.** 대신 **방법**이 그 일을 한다 —
어떻게 얻었는지 정확히 쓰면 무엇을 말할 수 있는지가 따라 나온다.

### 5.3 닫는 블록 — "한계" 가 아니라 "다음"

`이 편의 한계` 를 폐지하고 **`다음 단계`** 로 바꾼다. 같은 정보를 **앞을 보며** 쓴다.

| 폐지 | 대체 |
|---|---|
| "편파가 미통제다" | "실측에서 VV/HH 2편파를 잰다" |
| "다중반사는 1회까지만 본다" | "1회 반사로 계산했다. 이면각 검증 통과(+0.08 dB)" |
| "σ 절대값이 검증되지 않았다" | "기준 구를 함께 재면 자체 앵커가 선다 (→ 06편)" |

**표 형식: `다음에 할 일 | 그러면 결정되는 것 | 어디서`.**

### 5.4 문장 규칙

| 규칙 | |
|---|---|
| **능동태·완료형** | "…를 계산했다", "…로 측정된다" |
| **완충어 금지** | ~라고 볼 수 있다 · ~인 편이다 · 대체로 · 어느 정도 · 아마 |
| **사과 금지** | 아쉽게도 · 불행히도 · 다만 유의할 점은 |
| **부정문보다 긍정문** | "가림 없이는 못 푼다" → "가림을 광선으로 푼다" |
| **한 문단 3문장 이하** | 넘으면 표로 |
| **범위는 조건절로** | "β ≤ 45° 에서 3.2 dB" (○) / "3.2 dB 이지만 넓은 각도에선 부정확" (×) |

### 5.5 금지

| 금지 | 대신 |
|---|---|
| **과정 서사** — "처음엔 …했다가 …로 바꿨다" | 현재 상태만 |
| **버그·수정 이력** | 코드 docstring 에 남기고 리포트엔 안 씀 |
| **"…하지 않는다" 로 시작하는 절** | 무엇을 했는지로 다시 쓴다 |
| 산문 속 숫자 나열 | **표** |
| 같은 말 재설명 | 앞 편 §번호로 링크 |
| 그림 1개에 질문 2개 | 그림 1개 = 질문 1개 |

### 5.6 인수인계 요건 (각 편 필수)

1. **모든 숫자는 출처 표시** — `값 ⟨outputs/xxx.json : key⟩`. 손으로 친 숫자 0개.
2. **모든 그림에 캡션 1줄** = 그 그림이 답하는 질문.
3. **§마지막 = `다음 단계` 표** (5.3).
4. **재현 블록이 실제로 돌아야 한다** — 명령을 복붙해서 그 JSON 이 나와야 한다.
5. 코드 참조는 `파일:줄` 로.

### 5.7 분량 상한

| | 상한 |
|---|---|
| 편당 마크다운 셀 | **25개** |
| 셀 하나 | **12줄** |
| 편당 그림 | **8개** |

넘치면 **내용을 줄이지 말고 편을 쪼개라**. 다만 6편 골격은 유지.

### 5.8 ⭐ 자기검사 — 쓴 뒤 이 셋을 돌린다

1. **부정문 세기** — "않는다 / 못한다 / 아니다" 로 끝나는 문장이 편당 **3개 이하**.
   넘으면 그 문장들을 긍정으로 다시 쓴다.
2. **첫 화면 시험** — 여는 블록만 읽고 "이 사람들이 무엇을 해냈는가" 에 답할 수 있나.
   답이 "무엇을 안 했는지 알겠다" 면 실패다.
3. **완충어 grep** — `~라고 볼 수 있 · ~인 편 · 대체로 · 어느 정도 · 아쉽게도 · 유의할 점`
   **0건**이어야 한다.
