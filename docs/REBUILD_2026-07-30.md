## 1. 왜 갈아엎나 — 실측한 현실

| | 현재 |
|---|---|
| 리포트 | 본편 **13편** + 부록 **8편** = 21 |
| 코드 | src 81파일 33,990줄 + benchmark 34파일 13,174줄 = **47,164줄** |
| 재생성 파이프라인 | **26단계**, 직렬 **11.9시간** |
| 미커밋 | 239파일 |

그리고 조사가 밝힌 것:

- **주장의 상당수가 방어 불가**다 — 절대 σ(앵커 1개), 밴드 기울기(측정의 3~8배), 자세별 바이스태틱(상반성 25 dB 위반)
- **검증되지 않은 축을 헤드라인으로 삼고 있었다**
- 게재된 선행 6편 중 **표적 산란을 계산한 것은 0편**이다 — 전부 재거나, 피팅하거나, 정확도를 주장하지 않는다

즉 **문제는 작업량이 아니라 "지지되지 않는 주장을 향해 작업량을 쏟고 있었다"** 는 것이다.

## 2. 새 골격 — 6편

기준: **각 편이 "무엇을 주장하고, 그 주장이 무엇으로 지지되는가" 를 한 문장으로 말할 수 있어야 한다.**

### 01 · 선행연구 — 무엇이 가능하고 무엇이 아닌가
**주장**: 드론 메쉬로 산란을 계산해 게재된 전례가 없고, 회피한 논문들은 각각 무엇을 포기했다.
**지지**: 아카이브 55편 census(정독 26편), 게재상태 PDF 메타로 확정.
**핵심 절**: §3 회피전략 카탈로그(측정 / 피팅모델 / 외부 full-wave 주입 / stock 방치 / 해석적 블레이드 / 표적모델 없음).

### 02 · 표적 모델 — 메쉬·엔진·앵커
**주장**: 자세 구조는 기하에서, 레벨과 주파수 의존성은 측정에서. 그 경계를 수치로 명시한다.
**지지**: kr 스윕(해석PO 대비 ≤0.201 dB, 21점 48입사) · PO 모델 바닥(밴드별 envelope) · Das 앵커.
**합침**: 현 02(메쉬)+03(형상검증)+06(RT 한계)+07(SBR 엔진)+08(RCS 결과).
⭐ **이 편의 존재 이유**: 우리만 가진 것 = **부품별 재질 + 광선추적 가림**. Proc.IEEE 조차 stock 이다.

### 03 · 조명원 — 세 파형과 그 대가
**주장**: 점유·대역폭·PRF·λ² 가 만드는 격차. **전부 σ 와 무관하게 정확한 양이다.**
**지지**: 파형 사양 + Sionna PHY 검증.
**합침**: 현 04+05.

### 04 · 검출기 — ECA · 거리도플러 · CFAR 교정
**주장**: 명목 Pfa 가 경험 Pfa 와 얼마나 다른지, 그리고 그것을 교정하지 않으면 파형 비교가 성립하지 않는다.
**지지**: `verify_cfar.json`(2717 s 실측), `verify_eca.json`, 모호함수.
⭐ **문헌 공백**: OpenISAC 은 `CFAR`·`false alarm`·`detection probability` 가 **0회**다. 실측 논문은 Pfa 통제가 불가능하다. **통제 시뮬만 할 수 있는 일**이다.
**합침**: 현 10+11 일부.

### 05 · 검출 결과 — 모노/바이 × 근/원거리
**주장**: 자유공간에서 어느 조명원·몇 개 수신기로 어느 거리까지 보이나.
**지지**: 검출 헤드라인 + 감도사슬 + 자유공간 기하.
**합침**: 현 09(일부)+11(일부)+12+13.
⚠ **밴드 간 비교는 앵커 σ 위에서만** 말한다.

### 06 · 실측 계획과 검증
**주장**: 무엇을 재면 시뮬의 어느 주장이 결판나는가.
**지지**: matrice4e·mini5pro 측정 설계(기준체·배경차감·원거리장·자세통제).
**역할**: 이 편이 **다음 라운드의 계약서**다.

## 5. ⭐ 서술 규약 — 인수인계 문서로 쓴다

사용자 지시: **"지금 레포트 서술 방식이 너무 구구절절이라서 보기 안좋다"**,
**"함께 작업해오던 사람이 아니여도 레포트만 보고 인수인계 받을 수 있게끔"**

이 두 문장이 규약의 전부다. **독자는 이 프로젝트를 오늘 처음 보는 사람**이고,
그 사람이 **리포트만 읽고 이어받을 수 있어야** 한다.

### 5.1 모든 편이 같은 6블록으로 시작한다

```
┌─ 한 줄 ─────────────────────────────────────────┐
│ 이 편이 답하는 질문 하나. 물음표로 끝난다.        │
├─ 결론 ──────────────────────────────────────────┤
│ 3~5줄. 숫자 포함. 여기만 읽어도 결론을 안다.      │
├─ 주장하는 것 / 주장하지 않는 것 ─────────────────┤
│ 2열 표. ⭐ 이 블록이 이 프로젝트의 정직성이다.    │
├─ 필요한 사전지식 ────────────────────────────────┤
│ 앞 편에서 무엇을 알고 와야 하나. 없으면 "없음".   │
├─ 재현 ──────────────────────────────────────────┤
│ 명령 한 줄 + 출력 JSON 경로 + 소요시간.           │
└─ 본문 ──────────────────────────────────────────┘
```

### 5.2 금지

| 금지 | 대신 |
|---|---|
| **과정 서사** — "처음엔 …했다가 …로 바꿨다" | 현재 상태만 |
| **버그·수정 이력** | 코드 docstring 에 남기고 리포트엔 안 씀 |
| 3문장 넘는 문단 | 끊거나 표로 |
| 산문 속 숫자 나열 | **표** |
| "~라고 볼 수 있다" 류 완충어 | 단정하거나, 모른다고 쓰거나 |
| 같은 말 재설명 | 앞 편 §번호로 링크 |
| 그림 1개에 질문 2개 | 그림 1개 = 질문 1개 |

### 5.3 인수인계 요건 (각 편 필수)

1. **모든 숫자는 출처 표시** — `값 ⟨outputs/xxx.json : key⟩`. 손으로 친 숫자 0개.
2. **모든 그림에 캡션 1줄** = 그 그림이 답하는 질문.
3. **§마지막 = "이 편의 한계"** — 무엇이 아직 안 되어 있나. 다음 사람이 이어받을 지점.
4. **재현 블록이 실제로 돌아야 한다** — 명령을 복붙해서 그 JSON 이 나와야 한다.
5. 코드 참조는 `파일:줄` 로. "어딘가에 있다" 금지.

### 5.4 분량 상한

| | 상한 |
|---|---|
| 편당 마크다운 셀 | **25개** |
| 셀 하나 | **12줄** |
| 편당 그림 | **8개** |

넘치면 **내용을 줄이지 말고 편을 쪼개라**. 다만 6편 골격은 유지 —
쪼갤 만큼 넘친다면 그건 그 편이 두 질문을 답하고 있다는 뜻이다.
