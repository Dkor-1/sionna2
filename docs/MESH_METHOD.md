# MESH_METHOD — 기체 하나가 메쉬가 되기까지 (재현 문서)

생성 2026-08-03. 대상 소스: `src/drone_cad.py`(1,848줄) · `src/drones.py`(996줄) · `src/cadkit.py`(373줄).
목적: **우리 메쉬 제작 방식을 재현 가능하게 적고, 손으로 조정한 상수를 전부 드러내는 것.**
시험(예: Phantom 3 σ 검증)이 의미를 가지려면 "무엇이 방법이고 무엇이 그 기체 하나에 맞춘 것인지"가
구분되어야 한다. 이 문서는 그 구분을 위한 것이다.

## 0. 판정 (먼저 적는다)

**이 과정은 새 기체에 기계적으로 적용되지 않는다.** 기체마다 손이 간다.

- 등록된 표적 **7종이 전부** 자기 전용 코드나 전용 수치표를 갖는다.
  - `_SHELL_SHAPE` 전용 항목: mini5pro · mavic4pro · matrice4e · phantom4 (4종)
  - `build_frame_cad` **최상위 전용 분기**: s1000plus · typhoonh480 (2종)
  - 전용 실측표 `X500V2`(51항목) + 전용 helper 2개: x500v2 (1종)
- 즉 **공용 기본경로(`_SHELL_DEFAULT` + 대각비례 암/모터 + 규약 다리)로만 지어진 표적은 하나도 없다.**
  그 경로는 지금 검증용 대조기체(M100 · M600)만 탄다.
- 그 공용 경로를 실제로 돌렸을 때의 정확도가 저장소에 측정돼 있다

- 정직하게 덧붙이면: **엔진 수준은 전이된다.** 익형 법칙, 불리언 합집합, 그룹→재질 규약,

## 2. 어떤 원시 도형에서 시작하나

`cadkit.py` 가 제공하는 원시 연산은 **8개**뿐이고, 드론 형상은 전부 이 조합이다.

| 원시 | 구현 | 쓰이는 곳 |
|---|---|---|
| `box(w,d,h)` | `trimesh.creation.box` | 짐벌 하우징·렌즈통·클램프·배터리·PCB·마스트 베이스 |
| `cyl(r,h,axis,seg)` | `trimesh.creation.cylinder(sections=seg)` | 렌즈·요크·스탠드오프·GPS 퍽·레일·비콘 |
| `sphere(r,subdiv)` | `trimesh.creation.icosphere` | 짐벌 볼·어안 반구·다리 발끝 |
| `capsule(r,h)` | `trimesh.creation.capsule(count=[24,24])` | 스키드 바·발 레일 (⚠ `_capsule_wt` 로 감싸 씀, §5) |
| `revolve(profile_rz, seg)` | 자작 — (r,z) 프로파일 z축 회전, **r=0 링은 apex 로 접음** | 모터 벨·프롭 허브·RTK 원통·모터 포드 |
| `loft(sections, n_pts)` | 자작 — (y,z) 폴리곤 단면을 x 를 따라 잇기 | 동체 셸·캐노피·프로펠러 블레이드 |
| `sweep(path, profile_fn)` | 자작 — 접선 + parallel transport 프레임 | 암·착륙다리·모터마운트 |
| `extrude_polygon` | `trimesh.creation.extrude_polygon`(shapely) | 카본 판(사각/팔각/물방울꼴) |

2D 단면은 shapely 로 만든다: `superellipse(a,b,n)`(동체 단면), `rounded_rect(w,h,r)`(암 단면,
`buffer` 기반 정확 오프셋), `Polygon`(익형·팔각판·물방울판), `Point().buffer()`(원형 튜브).

**중요**: 원시들은 **겹쳐 놓기만** 하고, 마지막에 그룹별 불리언 합집합(§10)으로 내부 면을 녹인다.
"먼저 정확한 솔리드를 설계하고 조립" 하는 것이 아니라 **"대충 겹쳐 놓고 합집합"** 이 이 방식의 본질이다.

## 3. 곡률·모따기를 어떻게 넣나

진짜 CAD 의 fillet/chamfer 연산은 **없다.** 곡률은 네 가지 수단으로만 만든다.

1. **초타원 지수 `n_pow`** — `superellipse`. n=2 는 타원, n>2 는 모서리가 둥근 직사각.
   기본 2.6, 기종별 2.9~3.4(`_SHELL_SHAPE.npow`). 동체 단면의 "각짐/둥긂"이 이 한 숫자다.
2. **CubicSpline 보간** — `spline_sections`. 6개 제어 스테이션의 (반폭, 반높이, 중심 z 오프셋)을
   `scipy.interpolate.CubicSpline` 으로 보간해 `n_sec` 개 단면을 만든다. 종방향 곡률의 출처.
3. **Taubin 스무딩** — `smooth(m, iters)` = `trimesh.smoothing.filter_taubin`.
   동체 `iters=4`, 캐노피 3, 평면형 셸(`_body_profiled`) 2. 수축이 적은 라플라시안 변형.
   ⚠ 이건 형상 **정의**가 아니라 후처리다 — 치수를 미세하게 움직인다(측정과 비교할 때 유의).
4. **shapely `buffer`** — `rounded_rect` 의 모서리 반경(암 단면), `Point().buffer()`(원형 튜브).
   `quad_segs`(4~10)가 원호 분해능을 정한다.

모따기(chamfer)는 **명시 폴리곤**으로만 존재한다:
- `_body_plate_stack(shape="rect", chamfer=…)` → 45° 코너를 잘라낸 **팔각 폴리곤**을 직접 만든다
  (X500 V2 제조사 STEP 실측 22.95 mm).
- `shape="octa"` → 정팔각 폴리곤을 꼭짓점 각도 22.5°+45k 로 직접 만든다
  (`cyl(seg=8)` 은 외접원 기준이라 맞변거리와 위상이 둘 다 틀려서 못 쓴다).

**불리언 합집합은 필렛을 만들지 않는다.** 두 파트가 만나는 자리는 날카로운 능선으로 남는다.
그 결과가 계측돼 있다: 표면적 중 **날카로운 능선에 접한 비율 0.36~0.62**
(`outputs/mesh_compare_cad.json` → `area_frac_sharp_edge`). PTD/ILDC 보정이 필요한 이유가 여기 있다.

## 4. 프로펠러 블레이드 단면·비틀림

`_blade()` — 익형 단면을 스팬을 따라 회전(피치)·축소(테이퍼)·후퇴(스윕)시키며 `loft` 로 잇는다.

**(a) 단면 = NACA-4 익형** (`_airfoil`)
- 두께 분포: 표준 NACA-4 다항식 `yt = 5t(0.2969√x − 0.1260x − 0.3516x² + 0.2843x³ − 0.1015x⁴)`
- 평균선: 표준 NACA-4 2구간 포물선, **캠버 포함** (`CAMBER_M=0.05`, `CAMBER_P=0.50`)
- 두께는 평균선에 **수직**으로 얹는다(단순 상하 오프셋이 아님)
- x 는 코사인 클러스터링(앞전 촘촘), 점 수 `pts=40` → 상·하면 합쳐 약 38점
- **피치축은 시위 30 % 지점** (`P[:,0] -= chord*0.30`)

**(b) 시위 분포** — `CHORD_RR`/`CHORD_FRAC` 15점 표를 **r/R** 기준으로 보간, `CHORD_MAX_OVER_R = 0.25`.
근거: 참조 프롭 3종 원통단면 실측(`outputs/reference_props.json`, `benchmark/measure_reference_props.py`)
— Holybro 1345 · 3DR Solo · Yuneec Typhoon H480. 곡선 자체는 **Solo 측정치**다.

**(c) 비틀림(트위스트)** — 정피치가 아니다.
```
θ(r) = atan( k(r/R) · P / (2πr) )        P = spec.prop_pitch_in × 0.0254 [m]
```
`k(r/R)` = 국소 기하피치 분포 `PITCH_RR`/`PITCH_K` 16점 표(Solo 실측). 루트에서 낮게 시작해
0.6~0.7 R 에서 최대(1.11), 팁에서 다시 하락(0.72). `pitch_m=None` 이면 옛 선형 워시아웃
(`pitch_deg=20 − twist_deg=13·tt`)으로 되돌아가지만 **현재 생산 경로는 쓰지 않는다.**

**(d) 두께비 테이퍼** — 루트 `TC_ROOT=0.095` → 팁 `TC_TIP=0.065`, 스팬 선형.
실측 대역: 1345 5.9~9.3 % · Solo 6.1~8.2 % · Typhoon 8.6~12.8 %.

**(e) 시미터 스윕** — `yc = sweep_frac · R · sin(π/2 · tt)`, `sweep_frac = 0.10`. **근거 없는 손조정값이다.**

**(f) 스팬 분해능** — `n_sec` 단면(생산 경로는 `build_propeller(n=10)` → `n_sec=20`, 마이크로도플러는 더 큼),
단면당 `n_pts=36` 재샘플.

**(g) 스윕디스크 정규화(기계적)** — 스윕과 팁 시위 후단 때문에 실제 최대반경이 R 을 넘는다.
그래서 **한 번 지어서 재고**(`r_max`) `scale = R/r_max` 로 되돌린다. 상수 보정이 아니라 측정-되돌림이라
법칙을 바꿔도 자동으로 맞는다. (이 처리 전에는 전 기종이 프롭 지름 +0.84 % 초과였다.)

**(h) 허브·조립** — `_prop_hub(r=0.085R, h=0.09R)` 회전체 + 블레이드 `prop_blades` 장을
`360/blades` 씩 z회전. 루트는 `root_frac=0.070`(허브 반경 0.085 R 보다 **안쪽**)에서 시작해
허브와 겹치게 둔다 → 합집합 후 한 솔리드. 반대 회전 프롭은 `_mirror_y`(**winding 반전 포함**).

## 5. 재질 그룹을 어떻게 붙이나

- 파트를 만들 때마다 `Assembly.add(mesh, group)` 로 **문자열 그룹 태그**를 단다.
  그룹은 면 단위로 `geom.Mesh.g` 에 보존된다(정점이 아니라 면에 붙는다).
- 그룹 → 재질은 `drones.DRONE_GROUP_MAT` 하나가 정한다:

  | 그룹 | 재질 | 비고 |
  |---|---|---|
  | body / canopy / gear / accent | plastic | 유전체 셸(투과 대상) |
  | arm | carbon | `spec.arm_style != "carbon"` 이면 파트가 **`body` 로 들어간다** |
  | motor / battery | metal | 배터리 파우치 포일은 GHz 에서 사실상 금속 |
  | prop | prop_plastic | 얇은 날개 |Γ| 0.25 보정 |
  | camera | camera_assembly | 금속 하우징 + 유리 렌즈 복합 |
  | pcb / fc | pcb | FR-4 + 구리 |
  | deck / gear_cf | carbon | 열린 프레임 전용 |

- 물성은 `materials.MATERIALS` 가 유일 진리원이고 **Sionna RT 와 PO 가 같은 곳에서 읽는다**
  (`drone_gamma_map` → `materials.gamma_po`). 렌더 색도 같은 그룹에서 나온다(`MATERIAL_COLOR`).
- **새 그룹은 세 곳에 등록해야 한다**: `DRONE_GROUP_MAT` · `build_frame_cad` 말미의 union 목록 ·
  `gazebo_export.DENSITY`. 하나만 빠지면 조용히 틀린다.

⚠ **실제로 그 함정에 걸려 있는 자리 (이 문서 작성 중 확인)**
union 목록은 `("body","arm","motor","camera","gear","canopy","accent","deck","gear_cf","fc")` 이고
**`battery` 와 `pcb` 가 빠져 있다.** 셸형 v2 경로는 `battery` 그룹에 상자를 **2개** 넣는데
(배터리 상자 + 마그네슘 구조판) 이 둘은 겹치고, 합집합이 안 되므로 **파묻힌 면이 그대로 남는다.**
검산(phantom4): 두 상자의 전체 표면적 합 ≈ 58,400 mm² ↔ 원장 `group_area_mm2.battery` = 59,075 mm²
— 즉 내부 면이 살아 있다. PO/SBR 이 그만큼 헛센다. (배터리는 σ 지배 부품이라 무시할 항이 아니다.)

⚠ 재질 단순화도 기록한다: typhoonh480 은 실물이 "노출 튜브만 카본, 뿌리 칼라·포드는 플라스틱"인데
현재는 `arm_style` 규약을 따라 **둘 다 한 그룹**이다(|Γ| 0.90 ↔ 0.28 = 10.1 dB 레버).

## 6. 삼각형 수·해상도 기준

**기준이 없다.** 분해능은 전부 **고정 리터럴**(`seg=`, `n_pts=`, `n_sec=`, `subdiv=`)이고
파장·기체 크기·주파수 어디에도 연동되지 않는다.

주요 고정값: `revolve seg` 12~64 · `cyl seg` 10~64 · `sphere subdiv` 2~3 ·
`loft n_pts` 36(프롭)/56(캐노피)/72(동체)/96(평면형) · `spline_sections n_sec` 20~30 ·
`sweep n_pts` 14~28 · `rounded_rect pts` 16~64 · `buffer quad_segs` 6~10 · `capsule count=[24,24]`.

결과(전 기종, `outputs/mesh_compare_cad.json`, 프롭 포함 전체 드론):

| 기체 | 삼각형 | 파트 | 그룹 | 면적가중 facet p50 | 5G에서 facet > λ/10 인 면적비 | sagitta p50 |
|---|---|---|---|---|---|---|
| x500v2 | 18,816 | 48 | 10 | 50.0 mm | 0.864 | 0.003 mm |
| phantom4 | 28,402 | 23 | 8 | 10.2 mm | 0.649 | 0.029 mm |
| mini5pro | 29,044 | 25 | 9 | 6.9 mm | 0.348 | 0.036 mm |
| mavic4pro | 29,932 | 20 | 8 | 9.0 mm | 0.579 | 0.060 mm |
| matrice4e | 30,714 | 25 | 9 | 10.5 mm | 0.739 | 0.055 mm |
| typhoonh480 | 34,732 | 29 | 9 | 21.1 mm | 0.771 | 0.075 mm |
| s1000plus | 35,370 | 49 | 10 | 78.5 mm | 0.986 | 0.012 mm |

**왜 그래도 되나 (중요)**: EM 계산은 이 삼각형을 그대로 쓰지 않는다.
`rcs_po.mesh_to_points(mesh, spacing)` 가 **런타임에 각 삼각형을 바리센트릭 격자로 다시 잘라**
λ 기준 간격으로 점을 깐다 — `rcs_sbr.DEFAULT_DIV = 12`(λ/12), report02 는 λ/16, 드론 PO 경로 일부는 λ/7.
즉 **삼각형 수는 EM 적분 밀도가 아니라 "곡면을 얼마나 정확히 닮았는가"(sagitta)와 능선 위치를 정한다.**
sagitta p50 이 0.003~0.075 mm(λ 의 10⁻⁴ 급)이므로 곡률 근사 자체는 충분하고,
실제 리스크는 **평평한 큰 판(s1000plus 카본판, x500v2 데크)에서 facet 가 λ/10 을 넘는 것**인데
이건 런타임 재샘플링이 흡수한다. 위상 예산 초과 면적은 phantom4 기준 0.0 이다
(`area_frac_phase_over_budget`).

메쉬 건전성 검사는 `src/mesh_check.py` 가 **부품(연결요소) 단위**로 한다: watertight · winding 일관성 ·
법선 바깥(부호 부피 > 0) · 퇴화면. 전체 드론은 원래 watertight 가 아니므로 전체 검사는 의미가 없다.

## 8. 새 기체를 넣으면 실제로 무슨 일이 일어나나

### 기계적으로 되는 것 (스펙만 채우면 끝)
1. 로터 각도·반경·z 오프셋 배치 (`rotor_deg`/`rotor_r_mm`/`rotor_z_mm`)
2. 프로펠러 전체 — 지름·날개수·피치만 주면 익형 법칙이 자동 적용, 스윕디스크 정규화까지 자동
3. 암 두께·모터 크기 — `arm_od_mm`/`motor_dia_mm`/`motor_h_mm` 를 주면 비례식을 덮는다
4. 그룹→재질→|Γ|→색 매핑
5. 그룹별 불리언 합집합, 정점 병합·퇴화면 제거·법선 정렬
6. 공식 외형 맞춤(있으면), 프롭 포함 높이 재풀이
7. 메쉬 검증(`mesh_check`), 그룹별 면적·facet 통계

### 손이 가는 것 (안 하면 조용히 틀리거나 예외)
1. **셸 단면 법칙 27개 숫자** — 안 만들면 `_SHELL_DEFAULT`(= Mavic 계열 옛 값)로 떨어진다. 예외 없음.
2. **짐벌** — `key ==` 분기가 없으면 `gimbal_style` 이 `'none'`/`'belly'` 가 아닌 한
   **`NotImplementedError`** 로 죽는다. `'belly'` 로 선언하면 s1000plus 비율(0.30·bw, 0.22·bh, 0.30·bl)이
   붙는데 그건 "대조 기체 실루엣 대역 맞추기용, RCS 표적 아님"이라고 코드가 스스로 적어 두었다.
3. **센서 배치** — 어안·LiDAR·그릴은 전부 기종 분기 안의 좌표 리터럴이다. 자동 배치 없음.
4. **착륙장치** — `gear` 종류를 고르고(6종), `gear_h_mm`(motor_legs·열린프레임은 **필수, 없으면 예외**),
   열린 프레임 `tall` 은 아예 **실측표 필수**(`NotImplementedError`: "판 치수 비율은 삭제했다").
5. **암 폭·단면비** — `_ARM_WIDTH`/`_ARM_SECTION` 에 안 넣으면 대각비례(과거 실측의 1.7~2.6배 오차 사례).
6. **내부 산란체** — 셸형이면 공용 비율 상자가 자동으로 들어간다. **틀려도 예외가 안 난다.**
7. **열린 프레임이면** `plate_mm` 5개 + `body_l/w/h_mm` 일치 + `arm_style='carbon'` 강제 + 전용 실측표.

**기종당 손으로 적어야 하는 숫자 규모**: 셸 표 27 + 암 4 + 짐벌 전용 함수 20~52 + 배치 좌표 38~61
+ 다리 5~10 + 스펙 필드 10 → **대략 100~160개.**
그리고 그 숫자들의 근거는 "제품 사진 3~5장에 픽셀 축척을 앵커링해서 재는 것"이다 —
자동화된 절차가 아니라 **사람이 사진을 보고 재는 절차**다.

## 9. Phantom 3 시험 결과는 다른 기체로 전이되는가

`benchmark/airframe_phantom3.py` 는 이 질문에 대해 **스스로 답을 적어 두었다.**

- P3 에서 **측정/공표인 것**: 대각 350 mm · 높이 200 mm · 프롭 DJI 9450 (240 mm / 5.0 in) ·
  45° X 고정암 · 무게 1280 g.
- P3 에서 **상속인 것**(`SHAPE_DONOR = "phantom4"`): 셸 단면 법칙(`_SHELL_SHAPE["phantom4"]`) ·
  암 폭(`_ARM_WIDTH["phantom4"]`) · 암 단면비(`_ARM_SECTION["phantom4"]`) · 아치 다리 비율(`_gear_arch`).
  **저장소에 Phantom 3 사진이 한 장도 없다.**
- 즉 P3 메쉬는 "**Phantom 4 형상표에 P3 제원을 얹은 것**"이다.

따라서:

1. **P3 σ 가 실측(Das WCL 2026 · Yuan EuCAP 2025)과 맞는다** ⇒ 검증되는 것은
   "**P4 형상표 + 우리 엔진(익형 프롭·불리언·재질 |Γ|·λ/12 샘플링·PO/SBR)**" 조합이다.
   전이 범위는 **같은 형상 가족**(350 mm 급 · 일체형 흰 셸 · 고정 X 암 · 9450 프롭 · 아치 다리)까지다.
2. **Mini 5 Pro · Mavic 4 Pro · Matrice 4E** 로는 형상표가 통째로 다르므로 직접 전이되지 않는다
   (사진 일치도도 50~63 %). **S1000+ · X500 V2 · Typhoon H480** 은 아예 다른 코드 경로다.
3. **엔진 수준의 결론은 전이된다**: 익형 프롭 법칙(참조 프롭 3종 실측), 불리언으로 내부 면 제거,
   그룹→재질 |Γ| 단일 진리원, 런타임 λ 재샘플링, 1차 PTD 모서리항(untruncated Michaeli PTD-EEC) 필요성 —
   이것들은 형상표와 독립이므로 P3 결과가 지지/반증할 수 있다.
4. **전이되지 않는 것**: "우리가 임의의 기체 형상을 σ 수준으로 재현한다"는 주장.
   그 주장을 지지하려면 **형상표가 다른 기체**(다른 셸 법칙 + 다른 짐벌 분기)에서 두 번째 실측 앵커가 필요하다.
5. 그리고 P3 자체에 통제되지 않은 항이 남아 있다: 논문들이 "DJI Phantom 3"라고만 적어
   **변종(Standard/4K/Advanced/Professional)이 미상**이다.

**정직한 문장 형태**: "우리 방식이 실측 σ 를 ±X dB 로 재현한다"가 아니라
"**P4 사진실측 형상표에 P3 제원을 얹은 메쉬가** 실측 σ 를 ±X dB 로 재현한다.
같은 형상표를 쓰지 않는 기체에는 이 수치가 그대로 옮겨가지 않는다."

## 10. 이 문서가 남기는 미해결 항목

1. **battery/pcb 그룹이 불리언 합집합 목록에서 빠져 있다** (§5). 셸형 v2 는 겹치는 금속 상자 2개가
   내부 면을 유지한 채 PO/SBR 에 들어간다. 면적 검산으로 확인(58,400 ↔ 59,075 mm²).
2. **내부 산란체 3상자가 전 셸형 공용 비율**이고 기종별 근거가 없다 — σ 지배 부품인데 그렇다.
3. `outputs/real_cad_compare.json`(typhoon vs 실물 CAD, d_σ −0.40 dB · RMS 5.16 dB)은
   **mtime 이 `drone_cad.py` 보다 오래됐고**(07-31 02:46 ↔ 08:04) 그 안의 `n_faces_ours`(15,580)도
   현재 값(34,732)과 다르다 → **낡은 원장**이다. 인용하려면 재생성 후 인용할 것.
4. Taubin 스무딩이 치수를 미세하게 움직인다 — 사진/CAD 실측치와 최종 메쉬 사이의 계통오차원이지만
   정량되지 않았다.
5. 공용 경로(`_SHELL_DEFAULT`)의 정확도는 M100/M600 두 점밖에 없다(−3.1~−3.5 dB 면적, 7~10 dB RMS).
