# 0936 경로 출처 (2026-09-15) — ⭐**스펙트럼의 각 줄이 어디서 왔나**
#
# 사용자 결정(2026-09-15): 커널은 다른 논문으로 가고, 이 쪽은 **PathSolver 만으로** 간다.
# ⭐그때 광선 추적기만이 가진 것이 **경로별 출처**다 — 실측은 「무엇이 돌아왔나」만 알지
#   「무엇에 맞고 왔나」는 모른다. 우리는 그 장부를 갖고 있으면서 한 번도 안 열었다.
#
# 무엇이 되나 (2026-09-15 확인):
#   · 생산 경로가 드론을 **부위마다 이름 붙은 별개 물체**로 올린다 —
#     matrice4e_{accent,battery,body,camera,canopy,gear,motor,pcb,prop} 아홉.
#   · PathSolver 의 `objects` 가 번호를 돌려준다. ⛔⛔**그 번호는 이름 목록의 순번이
#     아니다** — 아래 「철회」 참조.
#
# ⛔⛔철회 (2026-09-15) — 이 발주서가 적었던 「camera 66.6 % · motor 14.1 %」를 **버린다.**
#   세 가지가 겹쳐서 틀렸다. 하나라도 있으면 인용 못 한다.
#   ① **이름표가 밀렸다.** `objects` 가 주는 것은 `object_id` 이고, 그것은 씬의 이름 목록
#      순번이 **아니다**(미쓰바가 전역으로 매기는 자리 번호다 — sionna/rt/scene_object.py:134).
#      우리 드론 씬에서 순번은 0~8 인데 id 는 **1~9** 라 정확히 한 칸 밀린다. 실측 —
#        id 3 → 옛 읽기 camera / **실제 motor**       id 6 → 옛 battery / **실제 gear**
#        id 7 → 옛 pcb    / **실제 battery**          id 9 → 옛 **범위 밖** / 실제 prop
#      ⇒ 「camera」 라 적은 것은 camera 가 아니다. 그리고 **prop 은 배열 밖으로 떨어져
#        조용히 사라진다** — 로터 줄을 보려고 만든 발주서에서 하필 그 부위다.
#   ② **셈법이 뜻을 뒤집는다.** 경로별 |a|² 몫은 **결맞지 않은** 분율이고, 수신 전력
#      |Σ a·e^{−j2πfcτ}|² 에 각 부위가 **보태는 몫**과 다르다. 우리 메쉬에서 직접 쟀다
#      (앙각 −30 · 깊이 1): body 가 결맞지 않은 몫 **70.13 %** 인데 결맞은 몫은
#      **−1.3536**(음수)이고, gear 는 14.24 % 인데 **+1.2517** 이다. 부호가 뒤집힌다.
#      ⇒ 「되돌아온 전력의 몇 %」라는 말 자체가 분모·합산 규약 없이는 뜻이 없다.
#   ③ **되살릴 수 없다.** 그 수를 낸 스크립트는 커밋된 적이 없고
#      outputs/path_provenance/ 는 비어 있다. 다시 «돌릴» 수는 있어도 «되계산» 은 못 한다.
#   ⚠깊이 2 부터는 **한 경로가 두 부위를 맞는다** — 실측 깊이 2 에서 418 경로 중 23 개
#     (5.50 %) · 깊이 3 에서 443 중 43 개(9.71 %). 이 발주서 16 줄 중 **8 줄이 깊이 2** 다.
#     ⇒ 부위별로 가르려면 **배분 규칙을 먼저 정해야 한다.** 규칙 없이는 수가 아니라 착시다.
#   ✅다행히 이 수는 덱·레포트·원장 어디에도 안 들어갔다(pptx 173 개를 풀어 확인: 0 건).
#     남은 자리는 이 줄과 커밋 b5cdbd2a 의 메시지뿐이고, 이 철회가 그 둘을 덮는다.
#
# 이 발주서가 사는 것: `--dump-paths 64` 로 **자세 64 개**의 경로 출처를 곁파일에 남긴다.
#   ⛔샤드 형식·팔 이름은 안 바뀐다 — outputs/path_provenance/ 에 따로 쓴다.
#     그래서 이 줄들은 **기존 칸을 다시 굽는 것**이고, 원장에는 새 행이 안 생긴다.
#     ⇒ ⛔`--overwrite` 를 준다(같은 이름이라 안 주면 「건너뜀」이다).
#   ⛔⛔**「같은 설정이면 E 가 같은 값이 나온다」는 철회한다** (2026-09-15).
#     그 근거로 든 「반복의 흔들림 0.00000 dB」는 **레벨**의 이야기였고, 표시 자릿수에
#     가려진 값이었다. 창고를 다시 훑어 재니 —
#       · 반복 팔 ↔ 원본 **152 칸 중 배열이 같은 칸 0 개** (복소 상대 L2 최대 1.28e−02)
#       · 지면 반복은 **자세 8,192 개 중 182 개에서 경로 «개수» 가 달랐다** — 반올림이 아니다
#       · 한 자세의 레벨 차가 0.0144 dB 인데 칸 전체 합으로는 −4.3e−08 dB 로 읽힌다
#     ⇒ `--overwrite` 는 **비교 원본을 지운다.** 이 묶음을 돌리기 전에 원본을 어디에
#       남길지 정한다(따로 보관하거나 별도 출력 경로).
#
# 고른 칸 8 개 — 「무늬가 보이는 곳」과 「묻히는 곳」을 짝으로:
#   빈 하늘 −30·−60 (무늬가 보이는 곳) · 실외 −30·−60 (묻히는 곳)
#   지면만 −30·−60 · 건물만 −60 · 협곡 −60 (무엇이 묻는지 가르는 곳)
# 16 줄 · 전부 깊이 2 또는 1 · 어림 24 일꾼시간.
# ⛔el 0 안 산다(GATES_0902). ⛔뮌헨 안 산다.
#
# ⛔⛔**이 발주서는 지금 세워 뒀다** (2026-09-15). 돌리기 전에 둘을 정해야 한다:
#   ⓐ 덮어쓰기 — 위의 철회 참조. 비교 원본을 어디에 남길지.
#   ⓑ 시간축 — `--dump-paths 64` 는 조각마다 **자세 130 개 간격**으로 남긴다(실측).
#      유효 표집률 19,700/130 = **151.538 Hz**, 나이퀴스트 75.769 Hz 다. 이 기체의 날개
#      통과율 126.667 Hz 도 그 위이고, 덱이 쓰는 날개 끝 주파수 1,228.72 Hz 는 **16.2 배**다.
#      두 조각을 합쳐도 간격이 1 과 129 로 고르지 않아 보통 FFT 로 못 읽는다.
#      ⇒ 부위별 스펙트럼을 보려면 **모든 자세의 부위별 복소 합**을 따로 작게 남겨야 한다.
#        (자세 8,192 × 부위 9 × complex64 ≈ 590 KB — 값싸다.)
# ⭐부위 이름표 자체는 고쳤다 — 자세마다 매핑을 떠서 안정된 부위 번호로 적는다
#   (benchmark/elevation_sweep_md.py 의 경로 출처 블록).
