#        configuration, so that later aiming choices can be computed instead of bought? 52 ms records with path lists.

# Purpose, and what the result changes.
#   The X410 demonstration has to put an antenna on a mast and point it somewhere. Every aimed cell in storage points exactly at
#   the drone; every off-aim cell in storage (0954, 0956, 0938, 0940) is at 15 m, 60° or 15° below, at the Sionna default 0.1 m
#   drone slab, with no path lists, and tilts only DOWNWARD. Nothing tells us what happens at the low elevation the demonstration
#   actually works at, and nothing tells us what happens when the antenna is tilted UP, away from the ground.
#   This file buys the four cheapest cells that can answer it: aim −10 and aim +10, each with open sky and with flat ground, at
#   the geometry 0962 already holds at zero offset.
#   What the result changes. The decision is whether a future aiming choice (a fixed mechanical down-tilt, a mast that points
#   above the drone to keep the ground out of the main lobe) can be COMPUTED on CPU from the stored path lists and the tr38901
#   formula, or whether each aiming configuration has to be bought as a GPU cell. Check W1 below decides that. If W1 holds, no
#   further aim cell is bought at this geometry and the antenna question moves to CPU re-weighting of 0962's lists (the same
#   route 0962's W check opens for the pattern); measured antenna patterns, when the specifications arrive, then go through the
#   same route. If W1 fails, aiming has to come from cells, the ±5° extension below runs, and no computed aiming number is
#   written anywhere.
#   ⚠This file does NOT decide a mast design. Two offsets at one range, one elevation, one azimuth, one airframe, with a
#   stand-in pattern, are not an antenna-installation study.
